## 四、比 `subst.exe` / `mklink /J` 更稳的三个改动（含步骤与验证）

1. **映射清单存在工具里，而不是每次手跑命令**：ScsSubst 把映射存成列表，开机自启时按列表重建盘符 → **下次登录盘符自动回来**；底层映射和 `subst.exe` 一样是会话级的（注销或重启即失效），`subst.exe` 是会话级映射，重启即失效，`mklink /J` 建的是 junction，还得自己配启动项。
2. **计划任务和服务看不到这个盘符**：`subst` 建的是当前登录会话里的 DOS 设备映射，换一个账号或服务会话就根本不存在 `X:`；ScsSubst 是同一套会话级机制的图形界面，Session 0 的服务和计划任务同样看不到它，这类任务要跑在同一个用户的交互式会话里。
3. **不用提权，也不用自己维护启动脚本**：写 `HKLM\...\Run` 或 `schtasks /create /sc onstart /ru SYSTEM` 都要管理员权限；ScsSubst 用你自己的 Windows 账号挂载即可（官方 FAQ：挂载不需要管理员权限）。

**验证三步（不改任何配置就能查）**

- `subst` —— 看当前会话里到底有哪些映射；
- `whoami` —— 看这个上下文用的是哪个身份；
- 在任务里同时记录 `whoami` 与 `subst` 的输出；看不到 `X:` 就是会话隔离，不是脚本写错。
